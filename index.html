TL;DR: LatentShield makes latent multi-agent collaboration monitorable: agents communicate in latent space within each MDU, while safety checks precede the token-space decisions passed between MDUs.

How LatentShield works

Latent communication stays within each Multi-Agent Decision Unit (MDU).
LatentShield checks the contributors’ trajectory before each decision is passed downstream.

Abstract

Learning to monitor latent collaboration

A small trainable readout connects agent representations to an existing safety model. The agent backbone and Llama Guard remain frozen.

01

Pool what matters

A learned query attends over the contributor states, turning a variable-length trajectory into one fixed-size representation.

02

Align with a safety model

A two-layer MLP maps the pooled vector into Llama Guard’s residual stream. Its frozen remaining layers estimate harmful-compliance risk.

03

Intervene before generation

When risk exceeds a validation-selected threshold, add a safety instruction to the decision node. Otherwise, generation proceeds normally.

Monitoring without intermediate text decoding. The monitor operates directly on the contributor latent trajectory. The intervention augments the decision node’s prompt while preserving its latent context.

MFR = ¼ (HB-ASR + SR-ASR + ORB-RR + PH-FRR). HarmBench and StrongREJECT measure harmful compliance; OR-Bench-Hard-1K and PHTest measure over-refusal. pXX targets XX% false positives on benign validation trajectories. Each threshold remains fixed for test evaluation; it is not a test-time refusal rate.
